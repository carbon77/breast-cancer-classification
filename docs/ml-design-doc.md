# ML Design Doc: классификация опухолей молочной железы по УЗИ

**Связанный тикет:** `UNI-31`
**Статус:** проектное решение; фактические метрики будут добавлены после экспериментов.

## 1. Назначение и контекст

Проект исследует подходы глубокого обучения для многоклассовой классификации УЗИ-изображений молочной железы и демонстрирует выбранную модель в веб-приложении. Исходный набор данных — [Breast Ultrasound Images Dataset](https://www.kaggle.com/datasets/aryashah2k/breast-ultrasound-images-dataset) с изображениями в PNG и ground-truth масками. В задаче классификации целевой переменной является класс изображения; маски не используются как вход модели по умолчанию.

Приложение предназначено для исследовательского анализа и демонстрации ML-пайплайна. Оно **не является медицинским изделием**, не ставит диагнозы, не выбирает лечение и не заменяет заключение врача.

## 2. Проблема, ценность и границы

### Проблема

Нужно сравнить на одних и тех же данных и с одинаковой схемой оценки:
1. базовую CNN, обученную с нуля;
2. предобученную CNN с transfer learning (например, ResNet, EfficientNet или DenseNet);
3. Vision Transformer (ViT) с transfer learning — обязательную продвинутую модель.

### Ценность

- Воспроизводимый pipeline подготовки данных, обучения и оценки.
- Сопоставление качества, времени инференса и размера checkpoint.
- Исследование влияния предобработки и аугментаций.
- Загрузка изображения, показ предсказанного класса и оценок модели.
- Тепловая карта, помогающая визуально исследовать области изображения, повлиявшие на предсказание.
- Артефакты экспериментов: код, конфигурации, веса, метрики и отчёт.

### Входит в scope

- Валидация структуры и качества датасета, EDA, поиск возможных дубликатов и проверка дисбаланса классов.
- Разделение данных, preprocessing и аугментации только для train.
- Обучение и сравнение трёх указанных семейств моделей.
- Оценка на отложенной выборке, сохранение лучшего checkpoint и метаданных эксперимента.
- Streamlit UI и отдельный FastAPI backend для инференса.
- Визуализация объяснения предсказания с помощью тепловой карты для поддерживаемых архитектур.

### Не входит в scope

- Клиническая валидация, сертификация и использование в медицинской практике.
- Диагнозы, рекомендации по лечению и автоматические клинические решения.
- Обучение на персональных данных вне открытого датасета.
- Сегментация как отдельная задача и отображение диагностических контуров.
- Гарантии переноса качества на другие клиники, аппараты или популяции.

## 3. Пользователи и сценарии

### Исследователь / специалист по компьютерному зрению

Проводит EDA, запускает обучение, сравнивает эксперименты, выбирает модель по установленным критериям и сохраняет воспроизводимые артефакты.

### Пользователь приложения

1. Открывает Streamlit-интерфейс.
2. Загружает валидное УЗИ-изображение в PNG.
3. Видит превью, предсказанный класс `normal`, `benign` или `malignant` и оценки для всех классов.
4. Открывает тепловую карту, наложенную на исходное изображение, и включает/выключает её отображение.
5. Видит метод построения карты и предупреждение о том, что визуализация не является медицинской разметкой или подтверждением диагноза.

## 4. Контракт модели

### Вход

- Одно успешно декодируемое УЗИ-изображение.
- На первом этапе поддерживается PNG.
- Перед инференсом изображение приводится к размеру, каналам и нормализации, сохранённым с checkpoint.
- Пустой, повреждённый или неподдерживаемый файл отклоняется с понятной ошибкой.

### Выход

Успешный ответ классификации содержит предсказанный класс, оценки и версию модели. Если построение тепловой карты включено и поддерживается моделью, ответ дополнительно содержит объект `heatmap`:

```json
{
  "predicted_class": "benign",
  "probabilities": {
    "normal": 0.03,
    "benign": 0.91,
    "malignant": 0.06
  },
  "model_version": "cnn-<checkpoint-id>",
  "heatmap": {
    "available": true,
    "method": "grad-cam",
    "format": "png",
    "image_base64": "<base64-encoded-overlay>"
  }
}
```

Если карта недоступна, `heatmap.available` равно `false`, а причина может быть передана в поле `reason`. Для клиента отсутствие карты не должно означать неуспешную классификацию. Формат изображения и кодирование фиксируются в API-схеме.

`predicted_class` всегда один из `normal`, `benign`, `malignant`. Оценки в `probabilities` — выход модели, а не клинически откалиброванные вероятности; отсутствие калибровки явно указывается в UI.

## 5. Тепловые карты объяснения предсказаний

Тепловая карта (Explainability heatmap) визуализирует области входного изображения, которые сильнее повлияли на оценку выбранного класса. Она строится после классификации для предсказанного класса и накладывается на исходное изображение с сохранением его видимости.

### Методы

- **CNN:** базовый метод — Grad-CAM или совместимый вариант, использующий градиенты целевого класса и активации выбранного сверточного слоя.
- **ViT:** Grad-CAM не переносится автоматически на любую конфигурацию трансформера; для поддерживаемых вариантов может использоваться attention rollout или другой отдельно проверенный метод.
- Метод объяснения и целевой слой/конфигурация фиксируются в метаданных эксперимента и доступны в результате.

Для обычной классификации градиенты не требуются. При построении Grad-CAM backend должен выполнять отдельный контролируемый проход с включённым вычислением градиентов для целевого класса; нельзя оборачивать этот проход в режим, полностью отключающий градиенты (например, `torch.inference_mode()`). Модель при этом остаётся в evaluation mode.

### Отображение в UI

- Тепловая карта накладывается на исходное изображение.
- Пользователь может скрыть/показать наложение; прозрачность подбирается так, чтобы исходное изображение оставалось различимым.
- Рядом отображаются метод построения и пояснение назначения визуализации.
- Если метод не поддерживается или карта не построена, результат классификации остаётся доступным, а UI сообщает о недоступности карты.

### Ограничения

Тепловая карта отражает вклад областей изображения во внутреннее решение модели. Она **не является сегментацией опухоли**, не определяет достоверные границы образования и не доказывает правильность предсказания. Визуально убедительная карта не подтверждает наличие патологии и не должна использоваться для клинических решений. Ground-truth маски датасета не следует выдавать за результат Grad-CAM или использовать как его замену.

## 6. Оценка и выбор модели

Все модели сравниваются на одинаковой test-выборке. Основная агрегированная метрика — **macro-F1**; вместе с ней фиксируются Accuracy, precision/recall/F1 по каждому классу, confusion matrix, время инференса на изображение и размер checkpoint. Выбор нельзя делать только по Accuracy: учитываются ошибки каждого класса и вычислительная стоимость.

Для тепловых карт проверяются корректность размеров, совмещения с исходным изображением, цветового наложения и стабильность построения. Если имеются подходящие размеченные области и согласован протокол, дополнительно может оцениваться локализация; без такого протокола карта рассматривается как качественный инструмент объяснения, а не как измеренная сегментация.

Численные пороги успеха, определения метрик и правило выбора модели приведены в [goals-metrics-success-criteria.md](goals-metrics-success-criteria.md). Baseline, единый split и план экспериментов приведены в [baseline-experiment-plan.md](baseline-experiment-plan.md). Test-набор используется для финального сравнения, а не для многократного подбора гиперпараметров.

## 7. Риски и меры

| Риск | Мера |
| --- | --- |
| Малый датасет и переобучение | Аугментации только на train, регуляризация, transfer learning. |
| Дисбаланс классов | Анализ распределения и per-class метрик; при необходимости class weights или sampler, выбранный только по train. |
| Утечка между выборками | Split по пациенткам/исследованиям, если связь доступна; иначе зафиксировать ограничение. |
| Сдвиг домена | Не заявлять обобщение на другие аппараты, клиники и популяции. |
| Неверная интерпретация результата | Дисклеймер и запрет медицинских рекомендаций в UI. |
| Ложная уверенность в тепловой карте | Явно сообщать, что карта объясняет вклад областей в решение модели, но не является медицинской локализацией. |
| Ограниченные GPU-ресурсы | Сначала baseline CNN и transfer learning, затем ViT с учётом памяти и времени. |

Подробный путь данных приведён в [data-flow.md](data-flow.md), техническая схема — в [architecture.md](architecture.md).

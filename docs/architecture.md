# Архитектура системы

## Решение

Обучение и serving разделены. Обучающий код выполняется в GPU-среде (Google Colab или Kaggle Notebook) и не запускается при веб-запросе. Веб-приложение состоит из Streamlit UI и отдельного FastAPI backend: Streamlit не загружает модель и не вызывает inference-модуль напрямую.

```text
Пользователь
    |
    v
Streamlit UI
(загрузка, preview, результат, heatmap, disclaimer)
    |
    | HTTP multipart/form-data
    v
FastAPI backend
(/health, /model-info, /predict)
    |
    v
Inference service
(валидация -> preprocessing -> predict -> explain)
    |
    +--> Загруженный checkpoint выбранной модели
    |
    v
Результат классификации + необязательная тепловая карта
    |
    v
Streamlit UI
(класс, оценки, наложение heatmap и предупреждение)
```

При запуске backend загружает checkpoint и preprocessing-конфигурацию один раз, переводит модель в evaluation mode. Для обычной классификации градиенты отключаются. Для Grad-CAM выполняется отдельный контролируемый проход с включёнными градиентами относительно целевого класса; его нельзя выполнять внутри `torch.inference_mode()`. Загруженные изображения и временные файлы тепловых карт не сохраняются постоянно без необходимости.

## Логические компоненты

| Каталог | Ответственность |
| --- | --- |
| `data/` | Локальная структура и инструкции получения датасета; крупные данные не хранятся в Git. |
| `src/data/` | Валидация датасета, split, загрузчики. |
| `src/preprocessing/` | Общие преобразования и аугментации. |
| `src/models/` | Архитектуры и фабрика загрузки модели. |
| `src/training/` | Обучение, validation, сохранение checkpoint. |
| `src/evaluation/` | Метрики, confusion matrix, сравнение экспериментов. |
| `src/inference/` | Загрузка checkpoint, preprocessing, классификация и построение тепловой карты. |
| `app/backend/` | FastAPI endpoints, схемы, inference/explainability и обработка ошибок. |
| `app/frontend/` | Streamlit UI, отображающий результат и наложение тепловой карты. |
| `artifacts/` | Конфигурации, метрики и веса; крупные файлы могут храниться вне Git. |
| `tests/` | Тесты preprocessing, контракта предсказания, explainability и ошибок загрузки. |

Это целевая логическая структура, а не утверждение, что все каталоги уже существуют.

## HTTP API

| Endpoint | Назначение | Успешный ответ |
| --- | --- | --- |
| `GET /health` | Проверка готовности сервиса. | Состояние сервиса. |
| `GET /model-info` | Получение имени/версии модели и поддерживаемых классов. | Метаданные модели, включая поддержку метода explainability. |
| `POST /predict` | Принимает одно изображение через `multipart/form-data`, запускает классификацию и построение карты, если оно поддерживается. | JSON с `predicted_class`, `probabilities`, `model_version` и необязательным объектом `heatmap`. |

Объект `heatmap` содержит `available`, `method`, `format` и закодированное изображение наложения; при недоступности карты возвращается `available: false`, но результат классификации сохраняется. UI позволяет показать/скрыть наложение и не трактует его как сегментацию или диагностическую разметку.

Backend ограничивает допустимый формат и размер файла, проверяет декодирование и возвращает подходящий HTTP status code с понятным сообщением. Ответ не должен содержать traceback или внутренние пути. CORS настраивается только если он действительно необходим.

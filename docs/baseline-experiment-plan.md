# Baseline и план экспериментов

**Связанный тикет:** `UNI-33`
**Статус:** проектное решение; фактические результаты экспериментов будут добавлены после обучения.

Документ опирается на [ML Design Doc](ml-design-doc.md) и [критерии успеха](goals-metrics-success-criteria.md). Здесь фиксируется только **план**: конфигурации, split и критерии принятия решений. Колонки «Результат» остаются пустыми до выполнения обучения в отдельных задачах.

## 1. Единый train/validation/test split

Split определяется один раз, версионируется и используется всеми моделями без изменений.

### 1.1. Состав данных

- Источник: Breast Ultrasound Images Dataset (Kaggle), около 780 изображений: `benign` ≈ 437, `malignant` ≈ 210, `normal` ≈ 133.
- Для классификации используются только исходные изображения. **Файлы масок (`*_mask*.png`, включая `_mask_1` и т. п.) исключаются** по шаблону имени и не участвуют ни в обучении, ни в оценке.
- Порядок индексов классов фиксируется: `0 = normal`, `1 = benign`, `2 = malignant`.

### 1.2. Пропорции

Стратифицированный split по классам, 70 / 15 / 15.

| Класс | Всего (≈) | Train (≈70 %) | Validation (≈15 %) | Test (≈15 %) |
| --- | --- | --- | --- | --- |
| normal | 133 | 93 | 20 | 20 |
| benign | 437 | 306 | 66 | 65 |
| malignant | 210 | 147 | 32 | 31 |
| **Итого** | **780** | **546** | **118** | **116** |

Точные числа уточняются после проверки целостности и удаления дубликатов (см. 1.3).

### 1.3. Защита от утечки данных

В датасете нет идентификаторов пациенток, поэтому split на уровне пациенток невозможен. Вместо этого:

1. До split проверяется целостность файлов (изображение декодируется, размер не нулевой).
2. Для каждого изображения считается перцептивный хэш (pHash, 64 бита).
3. Изображения с расстоянием Хэмминга ≤ 4 объединяются в группы (почти одинаковые снимки).
4. Split выполняется **по группам** со стратификацией по классу (аналог `StratifiedGroupKFold`): все изображения одной группы попадают в одну выборку.
5. Группа с разными метками (если встретится) выносится в список на ручную проверку и в split не включается до решения.
6. Оставшийся риск фиксируется как ограничение: изображения одной пациентки могут находиться в разных выборках, поэтому качество на test может быть завышено.

### 1.4. Фиксация и воспроизводимость

- Seed split: **42**. Split выполняется **до** любых аугментаций.
- Результат сохраняется в `artifacts/splits/split_v1.csv` со столбцами `filepath`, `class`, `group_id`, `split`.
- Хэш SHA-256 файла split записывается в конфигурацию каждого эксперимента и в метаданные каждого checkpoint.
- Split **не пересоздаётся** между экспериментами и между seed обучения. Seed обучения влияют только на инициализацию весов, порядок батчей и аугментации.
- Любое изменение split означает новую версию (`split_v2`) и повторное обучение всех моделей.
- Validation используется для early stopping, выбора checkpoint и подбора гиперпараметров. Test используется только для итоговой оценки: один запуск на каждую пару «модель × seed».
- Статистика по классам (размеры, дисбаланс) считается и сохраняется отдельно для train, validation и test.

## 2. Единый preprocessing

| Параметр | Значение |
| --- | --- |
| Размер входа | 224 × 224, прямое изменение размера без обрезки |
| Каналы | 3 (grayscale дублируется в три канала, если изображение одноканальное) |
| Нормализация baseline CNN | mean/std, вычисленные **только по train** |
| Нормализация предобученных моделей | mean/std, соответствующие весам модели (ImageNet) |
| Хранение | параметры preprocessing сохраняются вместе с checkpoint |

Preprocessing в serving-контуре должен точно соответствовать конфигурации, сохранённой с выбранным checkpoint.

### Аугментации (только train)

Умеренный набор, одинаковый для всех моделей: горизонтальное отражение (p = 0,5), поворот ±10°, случайное масштабирование/обрезка (масштаб 0,85–1,0), небольшое изменение яркости и контраста. Вертикальное отражение и сильные цветовые искажения не используются, чтобы не нарушать структуру УЗИ-изображения. Validation и test аугментациям не подвергаются.

## 3. Baseline: CNN с нуля

Baseline — минимально разумная модель, относительно которой измеряется выигрыш остальных подходов.

| Параметр | Значение |
| --- | --- |
| Архитектура | 3–4 блока `Conv → BatchNorm → ReLU → MaxPool`, затем `GlobalAvgPool` и `Linear(3)` |
| Размер модели | порядка 0,2–0,5 млн параметров |
| Инициализация | случайная, без предобучения |
| Loss | CrossEntropy с class weights (по обратной частоте классов в train) |
| Оптимизатор | AdamW, lr = 1e-3, weight decay = 1e-4 |
| Batch size | 32 |
| Эпохи | до 50 |
| Early stopping | по validation macro-F1, patience = 8 |
| Выбор checkpoint | эпоха с максимальным validation macro-F1 |
| Seed обучения | 42, 43, 44 |
| Среда | Colab Free, GPU; checkpoint сохраняется после каждой эпохи |

Результат baseline фиксируется как точка отсчёта. После получения baseline-метрик разрешён один пересмотр предварительных порогов M2–M5 из [критериев успеха](goals-metrics-success-criteria.md#61-критерии-качества-финальной-модели-на-test).

## 4. Последующие эксперименты

### 4.1. Transfer learning CNN (E2)

| Параметр | Значение |
| --- | --- |
| Архитектура | ResNet-18 с весами ImageNet; запасной вариант EfficientNet-B0 |
| Голова | замена последнего слоя на `Linear(3)` |
| Стратегия | Этап 1: backbone заморожен, обучается только голова (5 эпох, lr = 1e-3). Этап 2: размораживание всей сети (lr = 1e-4) |
| Остальное | AdamW, weight decay = 1e-4, batch 32, до 30 эпох, early stopping по validation macro-F1 (patience 6), class weights, те же аугментации |
| Seed | 42, 43, 44 |

### 4.2. Vision Transformer (E3)

| Параметр | Значение |
| --- | --- |
| Архитектура | `vit_tiny_patch16_224` или `vit_small_patch16_224` (библиотека `timm`) с предобученными весами |
| Голова | замена классификатора на `Linear(3)` |
| Стратегия | fine-tuning всей сети с warmup (2–3 эпохи) и cosine-расписанием |
| Параметры | AdamW, lr = 3e-5…1e-4, weight decay = 0,05, batch 16–32 (по памяти GPU), до 30 эпох, early stopping (patience 6) |
| Остальное | class weights, те же аугментации, mixed precision при необходимости |
| Seed | 42, 43, 44 |

### 4.3. Абляции (E4, опционально)

Выполняются только если остаётся бюджет Colab Free и только на лучшей модели из E2/E3, на validation:

- с class weights и без;
- с аугментациями и без;
- заморозка backbone и полный fine-tuning.

Абляции не меняют правила выбора модели и не используют test.

### 5.1. Что фиксируется для каждого запуска

Архитектура и гиперпараметры, seed обучения, хэш `split_v1.csv`, параметры preprocessing и аугментаций, время обучения, время инференса на CPU ноутбука (среднее и p95), размер checkpoint, версии библиотек и идентификатор checkpoint. По каждой модели строятся confusion matrix и таблица Precision/Recall/F1 по классам.

### 5.2. Правила интерпретации результатов

- Сравнение моделей идёт по mean ± std macro-F1 и Accuracy на test по 3 seed.
- Размер test мал (≈116 изображений, около 31 malignant): одна ошибка по malignant меняет Recall примерно на 3 п.п. Разница меньше std по seed не считается значимой, выводы формулируются осторожно.
- Test не используется для подбора гиперпараметров и early stopping.
- Если модель не выполняет M1–M3, она не выбирается без явной записи об отклонении.

## 6. Порядок выполнения

1. E0: проверка данных, дубликатов и создание `split_v1`.
2. E1: baseline CNN (3 seed).
3. Фиксация baseline-метрик и (при необходимости) единственный пересмотр порогов.
4. E2: ResNet-18 (3 seed).
5. E3: ViT (3 seed).
6. E4: абляции (если хватает ресурсов Colab Free).
7. E5: итоговое сравнение на test и выбор финальной модели.

## 7. Вне рамок

Реализация загрузчиков данных, обучение моделей, получение фактических метрик и развёртывание выполняются в отдельных задачах.
